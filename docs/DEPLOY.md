# Train a mini chat model and put it online (PyTensorForge Phase 7)

## What this is, and is not

This trains a small GPT-style model **from scratch** and serves it with a web chat UI and an
OpenAI-style API. It is not Claude/Sonnet or ChatGPT: those cost millions of dollars of GPU time.
PyTensorForge is a NumPy engine that runs on CPU. A model of a few million to a few tens of millions
of parameters, trained on good data, gives a small chatbot that holds a simple conversation.
Measure your speed before you commit to long runs: my tiny test model (48 wide, 2 layers) ran at
about 22,000 tokens/sec, and larger models will be much slower.

## Pipeline

    download data -> train tokenizer -> pretrain -> chat fine-tune -> export -> upload -> deploy

### 0. Setup
    pip install -e .          # or run `python cli.py ...` from the repo root
    pip install datasets      # only for downloading datasets

### 1. Download datasets
Pretraining text (plain language) and chat data (conversations):

    python scripts/download_datasets.py tinystories  --max-docs 200000 --out data/pretrain
    python scripts/download_datasets.py fineweb-edu  --max-docs 100000 --out data/pretrain
    python scripts/download_datasets.py smoltalk     --max-docs 50000  --out data/chat-raw
    python scripts/download_datasets.py no_robots                      --out data/chat-raw
    python scripts/download_datasets.py dolly                          --out data/chat-raw

* TinyStories is the best fit for a very small model. FineWeb-Edu adds general knowledge.
* SmolTalk, no_robots and Dolly are conversation/instruction sets.
* Check every dataset's license on its Hugging Face page. Avoid sets generated by models whose terms forbid training competitors.
* The downloader needs internet access to huggingface.co. I could not run it in my sandbox, so run it first on a small `--max-docs`.

### 2. Convert the chat data
    python scripts/prepare_chat_data.py data/chat-raw --out data/chat

This writes `data/chat/train/*.jsonl` and `data/chat/val.jsonl`, one conversation per line:

    {"messages": [{"role": "user", "content": "..."}, {"role": "assistant", "content": "..."}]}

### 3. Train the tokenizer (once, with the chat control tokens)
    python cli.py tokenize data/pretrain --output tokenizer.json --vocab-size 8192 \
        --special-token "<|system|>" --special-token "<|user|>" \
        --special-token "<|assistant|>" --special-token "<|end|>"

`tokenize` accepts one folder, so train the tokenizer on the pretraining folder. Never change the tokenizer after training starts.

### 4. Stage 1: pretrain (learn language)
    python cli.py train configs/pretrain.yaml
Resume after an interruption with `--resume`. Watch loss, tokens/sec and the ETA in the first minutes. If it is too slow, shrink `d_model`, `n_layers` and `context_length` in the config.

### 5. Stage 2: chat fine-tune (learn to answer)
    python cli.py train configs/chat.yaml
`init_from` loads the stage 1 weights. The model section in `chat.yaml` must match `pretrain.yaml`. Only the assistant replies are learned, and replies stop on their own.

### 6. Export (fp16 halves the file size) and test locally
    python cli.py export checkpoints-chat/checkpoint_latest.ptf --output exports/mygpt \
        --tokenizer tokenizer.json --dtype float16
    PTF_API_KEYS=choose-a-long-random-key python cli.py serve exports/mygpt --name my-gpt
Open http://127.0.0.1:8000 for the chat page. The export carries its own chat template, so the server needs no template setting.

### 7. Package and upload the model
    tar czf my-gpt.tar.gz -C exports mygpt
    sha256sum my-gpt.tar.gz
Upload the archive to a bucket (Cloudflare R2, S3, Backblaze) or a Hugging Face repo and note its https URL.

### 8. Deploy on Render
Copy these files into the repo root: `Dockerfile`, `.dockerignore`, `serve.yaml`, `start.sh`, `render.yaml`, `scripts/fetch_model.py`.
Push to GitHub (without the model). On Render choose New, then Blueprint, pick the repo, and enter `MODEL_URL` (and `MODEL_SHA256`) when asked.
Then copy the generated `PTF_API_KEYS` from the Environment tab: that is the key users or your app send as `Authorization: Bearer <key>`.

    curl https://<service>.onrender.com/v1/chat/completions \
      -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
      -d '{"model":"my-gpt","messages":[{"role":"user","content":"Hello"}],"max_tokens":80}'

To ship a new model, upload a new archive, change `MODEL_URL`/`MODEL_SHA256`, and redeploy.

### Letting real users in
The chat page asks for the API key, so users need a key from you. For a public site, run your own small backend or proxy that keeps the key secret and calls the API for visitors. Rate limits and request caps are set in `serve.yaml`. A persistent disk on Render needs a paid plan, and instance RAM must exceed model weights plus `kv_cache_budget_mb`.
